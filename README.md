# Распределенная система управления устройствами по CAN. Версия 1.0

## Цель проекта

Разработать модульную систему управления несколькими независимыми исполнительными устройствами через общую CAN-шину.

Каждый исполнительный узел имеет собственный микроконтроллер и локально управляет подключенным оборудованием, обрабатывает данные с датчиков и отправляет текущее состояние. 

Через веб-интерфейс узла диспетчеризации оператор имеет возможность управлять любым исполнительным узлом и видеть его состояние в данный момент.

## Текущий объём реализации

Реализован прототип системы с узлом диспетчеризации на ESP32 и одним исполнительным узлом на STM32.

Узел диспетчеризации предоставляет веб-интерфейс для ввода команд оператором, передаёт их по CAN и получает ответ от исполнителя. 

Исполнительный узел - контроллер шагового двигателя. Принимает команду, управляет шаговым двигателем (перемещает каретку в расчетную координату в мм) и возвращает результат операции.

Протокол CAN обеспечивает возможность отправки команд и прием ответов между узлом диспетчеризации и несколькими исполнительными узлами

#### Принцип работы

1. **Запуск системы.** ESP32 инициализирует CAN, подключается к Wi-Fi и запускает веб-сервер. STM32 инициализирует CAN, таймеры и управление двигателем.
2. **Подключение пользователя.** Пользователь открывает веб-интерфейс ESP32 и отправляет ручную команду либо запускает программу перемещений.
3. **Передача команды.** ESP32 формирует CAN-сообщение с командой (HOME, GOTO или STOP), номером транзакции и координатой, если она нужна.
4. **Обработка команды на STM32.** Микроконтроллер проверяет команду и запускает соответствующее действие. При GOTO он управляет шаговым двигателем через прерывания таймера.
5. **Возврат состояния.** STM32 отправляет по CAN подтверждение, текущий статус и рассчитанную координату.
6. **Обновление интерфейса.** ESP32 обрабатывает ответ и передаёт актуальные данные в браузер через WebSocket.
7. **Выполнение программы перемещений.** Если пользователь запустил последовательность координат, ESP32 после получения DONE для текущей команды отправляет следующую. Когда точки заканчиваются, программа завершается.

#### Режимы работы

Предварительно необходимо откалибровать систему. Для этого оператор нажимает кнопку `HOME`, после чего каретка начнет движение на пониженной скорости в сторону концевика(фотопрерывателя). При достижении концевика каретка остановится в позиции 0 мм.

1) **Ручной режим.** Оператор задает координату, и нажимает кнопку `GOTO`. Мотор переместит каретку в расчетную координату
2) **Последовательность.** Оператор задает последовательность из координат. По нажатии кнопки `START` каретка перемещается по всем в указанной очередности и останавливается в последней.

## Узел диспетчеризации на ESP32

ЗАГЛУШКА**Скриншот веб-интерфейса**

Логика работы заключается в 4 основных функциях:

1. **Раздача HMI-интерфейса.**
   
   При вводе IP-адреса платы в браузере, ESP32 считывает файлы интерфейса (`index.html`, `style.css`, `app.js`) со своей внутренней флеш-памяти (`LittleFS`) и отправляет их клиенту по протоколу HTTP. Браузер отрисовывает панель и открывает дуплексный канал WebSocket.

2. **Получение команды из браузера и парсинг.**

   Когда оператор задает команду через кнопки на сайте, браузер отправляет на ESP32 текстовую строку в формате JSON. WebSocket-сервер (`WebServer.cpp`) получает этот текст, парсит через библиотеку cJSON и передаёт в блок управления узлами `DeviceManager.cpp`.

3. **Отправка команды и прием ответов от узла по CAN.**
   
   Работа происходит по событийной модели (Event-Driven). Если оператор задал последовательность перемещений (например: 20 -> 60 -> 15 мм), программа берет координату из массива, составляет кадр и отправляет в шину CAN. Как только исполнитель присылает ответ об успешном выполнении, отправляет следующую координату.

4. **Прием телеметрии и Heartbeat шины CAN.**

  Каждые 50 мс STM32 отправляет телеметрию по CAN. ESP32 принимает эти пакеты, переводит в JSON и отправляет по Wi-Fi, обновляя цифры в веб-интерфейсе.
  Если при физическом разрыве шины ESP32 зафиксирует отсутствие этой циклической телеметрии, то выведет на экран ошибку `LINK_ERROR`.

#### Программная структура

## Исполнительный узел - контроллер шагового двигателя на STM32

Архитектурные детали:

1. Аппаратный приём и фильтрация CAN 
   
   STM32 находится в режиме аппаратной фильтрации (CAN-фильтр настроен на ID 0x201 - команду от узла диспетчеризации). Принятый кадр обрабатывается через механизм прерывания. Обработчик прерывания расшифровывает и сохраняет токен поступившей команды, код операции и цель в миллиметрах.

2. Конечный автомат (FSM)

   В любой момент времени контроллер может находиться только в одном из следующих состояний:
     - STARTUP (инициализация),
     - UNHOMED (выполнение перемещения заблокировано, т.к. контроллер не откалиброван (положение 0 мм неизвестно)),
     - HOMING (движение с пониженной скоростью в сторону концевика(фотопрерывателя), при его обнаружении происходит остановка и сохранение позиции 0 мм),
     - READY (ожидание команд, устройство откалибровано),
     - MOVING (выполнение команды),
     - FAULT (авария).
   
    Перед любым действием модуль `motion.c` проверяет текущее состояние системы. 
    Если система находится в состоянии `UNHOMED`, любые команды перемещения отклоняются и возвращается отказ `NACK` (0xFF).
    Команда исполняется только после успешного прохождения калибровки нуля (`HOMING`) и перехода привода в статус готовности `READY`.

3. Алгоритм движения:

    a. **Получение цели.** STM32 получает целевую координату в миллиметрах и переводит её в количество шагов с учётом коэффициента STEPS_PER_MM (у данной экспериментальной установки STEPS_PER_MM = 44.15 шага/мм)
   
   b. **Определение направления.** Сравнивает текущую и целевую позиции: если цель впереди — вращает двигатель в одну сторону, если позади — в другую.

    c. **Трапециевидный профиль скорости.** Расчет скорости шагового мотора происходит в обработчике прерывания таймера TIM2.
       Период таймера TIM2 определяет, как часто вызывается прерывание, в котором выполняется очередной шаг двигателя.
       Поэтому чем меньше период между прерываниями, тем выше скорость двигателя.
        - Разгон: период постепенно уменьшается — шаги выполняются чаще, двигатель ускоряется.
        - Постоянная скорость: период остаётся неизменным — двигатель вращается с постоянной скоростью.
        - Торможение: период постепенно увеличивается — шаги выполняются реже, двигатель замедляется.

   d. **Завершение**. Когда счётчик шагов достигает целевой позиции, STM32 прекращает движение, переходит в состояние `READY`.

    Для коротких перемещений разгон и торможение сокращаются или вообще не выполняются — мотор движется с начальной скоростью.

4. Отправка ответа и телеметрии
    При достижении целевой точки формируется пакет `DONE` (0x55) и отправляется по CAN узлу диспетчеризации.
    А также каждые 50 мс STM32 отправляет по CAN пакеты с текущим расчетным положением каретки.

## CAN-протокол

Используется CAN с номинальной скоростью 500 кбит/с и стандартными 11-битными идентификаторами кадров. 

#### Адресация

Идентификаторы кадра формируются на основе базового адреса и идентификатора узла. Это позволяет адресовать команды и получать ответы между узлом диспетчеризации и несколькими исполнительными узлами.

| Назначение кадра | Формула | Для исполнительного узла №1 | Для будущего Узла №2 
|---|---|---|----|
| Команда диспетчера к исполнителю | `0x200 + Node_ID` | `0x201` | `0x202` |
| Ответ исполнителю диспетчеру | `0x300 + Node_ID` | `0x301` | `0x302` |


#### Структура кадра команды (Диспетчер -> Исполнитель). Команда содержит 6 байт данных

| Элемент кадра | Содержимое |
|---|---|
| CAN ID   | `0x200 + Node_ID`                                                        |
| Байт 0   | `Токен` (номер транзакции)                                                                 |
| Байт 1   | Код команды (`0x01` = HOME, `0x02` = GOTO, `0x03` = STOP)               |
| Байт 2-5 | Целевая координата в миллиметрах (32-bit `int32_t` в формате Big Endian) |

<br>

#### Структура кадра ответа (Исполнитель -> Диспетчер). Ответ содержит 7 байт данных

| Элемент кадра | Содержимое |
|---|---|
| CAN ID   | `0x300 + Node_ID` |
| Байт 0   | `Токен` (номер транзакции)   |
| Байт 1   | Статус транзакции (`0xAA` = ACK / Принято, `0xFF` = NACK / Отклонено, `0x55` = DONE / Успешно завершено) |
| Байт 2   | Физическое состояние автомата привода (`0x01` = MOVING, `0x02` = READY, `0x03` = FAULT, `0x04` = UNHOMED) |
| Байт 3-6 | Текущая расчётная координата каретки в мм (Big Endian) |


<br>


#### Пример

Команда: `Транзакция №5. Переместить каретку Узла 1 на координату 170 мм`

| Значение (Hex) | Байт | Расшифровка | 
|---|---|---|
| 0x201 | CAN ID | База для адресации команд это 0x200. У контроллера шагового двигателя ID=1
| 0x05 | Байт 0 | Токен (номер транзакции)
| 0x02 | Байт 1 | Код команды GOTO 
| 0x00 | Байт 2 | Координата: Старший байт 4 (Big Endian)
| 0x00 | Байт 3 | Координата: Байт 3
| 0x00 | Байт 4 | Координата: Байт 2
| 0xAA | Байт 5 | Координата: Младший байт 1 (0xAA = 170 мм)


<br>

Ответ: `Транзакция №5. Успешно выполнена. Текущее состояние READY. Расчетная позиция каретки 170 мм`

| Значение (Hex) | Байт | Расшифровка | 
|---|---|---|
0x301 | CAN ID | База для адресации ответов это 0x300. У контроллера шагового двигателя ID=1
0x05 | Байт 0 | Токен (номер транзакции)
0x55 | Байт 1 | Статус транзакции DONE
0x02 | Байт 2 | Состояние READY 
0x00 | Байт 3 | Расчётная позиция: Старший байт 4 (Big Endian)
0x00 | Байт 4 | Расчётная позиция: Байт 3
0x00 | Байт 5 | Расчётная позиция: Байт 2
0xAA | Байт 6 | Расчётная позиция: Младший байт 1 (Каретка стоит в расчётной координате 170 мм)

## Защита и безопасность

- Если оператор запустил режим **Последовательность**, то ручной запуск каретки командой `GOTO` проигнорируется.
  
- Если во время перемещения каретки командой `GOTO` оператор задаст другую координату, то старое значение цели перепишется новым (оператор имеет право передумать и отправить каретку в другую сторону).
  
- Во время выполнения команды `GOTO` в Ручном режиме при нажатии кнопки `STOP` каретка остановится в текущем положении и сохранением координаты.

- При физическом разрыве шины связи в веб-интерфейсе отобразится ошибка `LINK_ERROR`.

- Разрешенный диапазон координат прописан программно. Для данной экспериментальной установки 0–170 мм.

## Ограничения текущей версии

- Физически реализован только один исполнительный узел — шаговый привод. Дополнительные узлы предусмотрены архитектурой, но ещё не реализованы полностью.
- Установка собрана как демонстрационный прототип. Перед использованием в реальном оборудовании требуется дополнительная проверка обработки ошибок, потери связи и безопасных состояний.
- Программный диапазон в текущей конфигурации — 0–170 мм.
- Программные пределы и датчик HOME не заменяют промышленную систему безопасности.
- У прототипа нет независимой обратной связи по положению и полноценной диагностики механического заклинивания.
- координата передаётся целым числом миллиметров. Если нужна дробная координата, например 12,5 мм, текущего формата недостаточно без изменения протокола или введения масштаба.
- При включении питания положение каретки считается неизвестным до успешного выполнения HOME
- Контроллер использует расчёт положения по количеству шагов; независимого измерения координаты нет.
- Программный диапазон не гарантирует защиту от механического выхода за пределы хода при потере шагов, проскальзывании механизма или неисправности датчика.
- Прототип не предназначен для применения в оборудовании, требующем сертифицированных функций безопасности.
